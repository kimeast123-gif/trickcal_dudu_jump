# 인수인계: 두두의 폴짝폴짝 대모험 (v1.5.0 기준, 2026-11-17)

Claude 앱 대화에서 진행한 리뉴얼 작업을 Claude Code로 넘기기 위한 문서입니다. 규칙과 명령은 `CLAUDE.md`, 여기는 배경과 이력, 남은 과제입니다.

## 1. 지금 상태

- 배포 버전 v1.5.0. 저장소 `trickcal_dudu_jump` (GitHub Pages). v1.4.2부터 Claude Code가 저장소를 clone해 직접 커밋한다.
- 스토리 6개 지역 + 엄마의 방 엔딩, 챌린지 모드(추억의 인내의 숲 2단계), 월드맵(v1.5부터 처음부터 열림), 월드1 수인숲 5개 스테이지, 월드2 「모나티엄의 야경」 긴 스테이지 1개(설계와 검수는 `docs/NIGHT_MONATIUM.md`).
- 왕사탕 135개, 황금 크레파스 12개(전부 모으면 특별 엔딩).
- 개발자(사용자)가 PC와 모바일에서 직접 플레이하며 피드백을 주는 방식으로 진행했다. 맵 점검은 v1.2.1에서 끝났다고 확인받았다.

## 3. 사용자가 정한 방향 (바꾸려면 먼저 물어볼 것)

- 스토리 모드의 재미는 "편안한 귀갓길 탐험과 수집", 챌린지 모드는 "정밀 컨트롤". 난이도 판단은 이 기준으로 한다.
- 피드백 중 인상 깊게 받은 원칙: "플레이하며 불합리하다는 느낌이 안 들게 유저 편의를 알게 모르게 봐줘야 좋은 게임". 코요테 타임, 점프 예약, 점멸 발판 유예(꺼진 뒤 0.14초), 터치 점프 최소 높이 보정이 이 원칙으로 들어갔다.
- 형태가 기능을 말해야 한다: 통과 가능한 발판, 점멸 발판, 낙사 구덩이는 생김새로 구분돼야 한다.
- 문구에서 "AI 티"를 싫어한다. 영문 대문자 머리말, 장식 기호, 중간점 나열, 버튼 화살표, "비공식 작품" 같은 메타 문구를 지웠다.

## 5. 남은 과제 (우선순위 순)

1. **실기기 성능 확인**: v1.4의 그래픽 최적화(큰 이미지 분할, 흐림 제거)는 헤드리스 브라우저에서 효과를 측정할 수 없다. 사용자에게 `?fps=1`로 연 화면 캡처(v1.4.2부터 맵 이름, 위치, 맵별 끊김, 화면 크기와 배율, 주사율까지 나온다)와 기종을 받아 판단한다. 평균 55fps 이상인데 끊기면 장면별 원인, 40fps 미만이면 기기 쪽. 느린 기기라면 저사양 모드가 끄는 효과(화면 0.1~0.3장 분량)로는 부족하니, 2단계로 내부 해상도를 960×540으로 낮추는 방안을 검토한다(메인 캔버스에 setTransform이 없어 넣기 쉬움).
2. **가상 패드의 확대 표시**: v1.3 이후 실제 확대는 막혔지만 패드 쪽에 확대 표시가 잠깐 뜬다는 보고가 있었다. v1.4에서 아이폰 텍스트 선택 돋보기 차단을 넣었으나 실기기 확인 전이다. 기종 확인 필요.
3. **모나티엄 배경이 거의 움직이지 않음**: 배경 한 장을 레벨 전체(2만 6천 px)에 늘려 매핑해서 패럴랙스 비율이 2% 수준. 코드로는 근본 해결이 안 되고 더 넓은 배경 원화가 필요하다. 에르피엔은 넓은 원화를 써서 괜찮다.
4. **모나티엄 B 구조물 화풍**: 철골 벽과 회색 빌딩 타일이 단색 벡터풍이라 회화풍 배경과 어긋난다. 원화 리터치 필요.
5. **수인마을 발판을 마을 사물로**: 지붕, 차양, 울타리를 발판으로 쓰는 재배치는 수집물 배치와 엮여 있어 보류했다. 사용자와 원칙을 정한 뒤 진행.
6. **고해상도 화면**: 캔버스는 1280×720 고정이고 devicePixelRatio 대응이 없다. 큰 화면에서는 늘려 보여 흐리다.
7. **화면을 꽉 채우지 않음**: 16:9 고정이라 긴 폰 화면에서는 양옆에 여백이 생긴다. 논리 해상도를 화면비에 맞게 넓히는 작업은 HUD 좌표가 고정값이라 범위가 크다.
8. **구조 부채**: 전역 스크립트, 로드 순서 의존, `typeof x === 'function'` 방어 코드가 많다. ES 모듈 전환은 큰 작업이라 기능 작업과 섞지 말 것.
9. **월드2 실기기 확인**: 야간 맵을 사람이 직접 해 보고 드론 사격 간격(v1.5.1에서 1.66초, 탄속 600px/s로 강화), 셔터 앞 대시 타이밍, 타워 이동 발판 속도가 "편하게 어렵다" 정도인지 사용자 피드백을 받는다. 수치는 `night-monatium.js`의 `DRONE`과 `mover(...)` 인자.
10. **보류한 UX 제안 (2026-11-17, 사용자 결정 대기)**: 일시정지의 "처음부터 다시"가 구간인지 전체인지 모호함(범위를 밝히는 문구, 진행이 사라지면 "메인화면으로"에 확인 단계). 남은 시간 표시(위쪽 호를 따라 움직이는 작은 해)가 "해 지기 전에 집에"라는 목표에 비해 약함. 스토리 모드의 편안함과 긴장 사이 정도를 사용자가 정해야 한다.

## 6. 측정 기준값 (v1.4.2, 비교용)

- 회귀 테스트 `tools/qa/regression.py` 26개 항목 전부 통과. 야간 맵: `night_hops.py` 56개, `night_checks.py` 25개 통과, `night_run.py` 연속 완주 75.5초.
- `perf_probe.py N 4` 6개 맵 평균 프레임: 수인숲 21, 수인마을 18.5, 모나티엄 A 21, 모나티엄 B 20.5(v1.4.1은 31), 에르피엔 A 19.6, 에르피엔 B 21ms.
- `perf_probe.py 2 4` (모나티엄 A, CPU 4배 감속, 소프트웨어 렌더링): 평균 프레임 약 20ms, 50ms 초과 0, 스크립트 약 2.4ms, 레이아웃+스타일 0.1ms 미만, 점프 탭 15회 중 놓침 0.
- 메모리 할당 초당 약 2~3.5MB, 가비지 컬렉션 초당 약 2회, 5초간 50ms 초과 프레임 0.

## 7. 도구 요약

| 명령 | 용도 |
| --- | --- |
| `python tools/qa/regression.py [단어...]` | 회귀 테스트. 단어를 주면 이름에 그 단어가 든 항목만(예: `dash`, `touch`, `mayo`) |

| `python tools/qa/perf_probe.py 2 4` | 폰 화면 성능 측정과 점프 놓침 수 |
| `python tools/qa/night_hops.py [단어]` | 야간 맵 발판 간 이동 56개(실패해야 하는 입력 포함) |

| `python tools/qa/night_run.py` | 야간 맵을 입력만으로 처음부터 클리어까지 연속 플레이 |
| `python tools/release.py v1.5.0` | 버전과 캐시 키 일괄 교체, 해시 목록 재생성 |

환경 변수: `GAME_ROOT`(기본 저장소 최상단), `QA_PORT`(기본 8765), `CHROME`(기본 Playwright 내장 Chromium).
게임 상태는 전역 변수로 직접 다룬다: `p`(플레이어), `platforms`, `actors`, `levels`, `levelIndex`, `state`, `cam`, `camY`, `keys`. 테스트 스크립트의 `play(page, level, x, y)`가 메뉴를 건너뛰고 원하는 위치에서 바로 플레이 상태로 만든다.

## 8. 배포 절차

1. 코드 수정 → `python tools/qa/regression.py` 전부 통과
2. `CHANGELOG.md` 맨 위에 새 버전 항목(한국어, 플레이어가 느끼는 변화 위주)
3. `python tools/release.py vX.Y.Z`
4. 커밋, 푸시 → Pages 배포 후 휴대폰에서 새로고침해 확인
