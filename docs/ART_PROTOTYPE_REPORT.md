## 0. v1.1 수정 (2026-11-22): 정령산에서 게임이 멈추던 문제

**증상 (사용자 보고)**: 정령산 시작 지점에서 점프해 다음 발판에 닿기 전에 화면에 배경만 남고 UI가 사라짐. 메뉴로 돌아가 다시 시작하면 정령산 화면이 그대로 남은 채 멈춤.

**원인**: 이 테스트 빌드의 코드(`art-prototype.js` v1) 문제였다. 배포본(261122)에는 없다.
- 동굴 이음매 자르는 자리를 고르려고, 동굴 발판이 처음 화면에 들어올 때 그림 픽셀을 브라우저에서 읽었다(`getImageData`).
- `index.html`을 파일로 바로 열면(`file://`) 브라우저가 그림 픽셀 읽기를 막고 오류를 낸다. 이 오류가 그리기 도중에 나서 게임 루프가 멈췄다. 출발 지점에서 오른쪽으로 가면 카메라에 산 속 동굴 발판이 걸리기 시작해 그 순간 멈췄고, 루프가 죽어 있어서 메뉴로 갔다 와도 마지막 화면이 남았다.
- 기존 검증은 모두 로컬 웹서버(`http://`)로 돌려서, 픽셀 읽기가 허용돼 이 경우를 놓쳤다.

**수정**
1. 브라우저에서 픽셀을 읽지 않는다. 자를 자리 표(393칸)를 승인 PNG에서 미리 계산해 코드에 넣었다(`tools/art_cave_cuts.py`로 재생성). 결과 그림은 v1과 픽셀 단위로 같다(띠 이미지 차이 0px).
2. 안전장치: 시제품 그리기에서 어떤 오류가 나도 그 종류(숲/동굴)만 끄고 배포본 그림으로 그리며 게임은 계속된다. 콘솔에 경고 한 줄만 남긴다. 일부러 오류를 내서 확인했다(게임 시계와 착지 정상).
3. 숲 그리기는 오류가 나도 캔버스 상태(`save/restore`)가 어긋나지 않게 했다.
4. 새 테스트 `tools/qa/art_file_open.py`: 파일로 열어 스토리 수인숲, 월드1, 정령산 동굴 두 곳을 돌며 게임이 계속 도는지 확인. v1에서는 동굴 2곳 FAIL(게임 시계 0초, 픽셀 읽기 오류), 수정본은 6/6 PASS.
5. 캐시 키 `art-prototype.js?v=art_v1_261122b`.

**정령산 자동 테스트 실패에 대해**: `spirit_checks.py`, `spirit_hops.py`의 대량 실패는 배포본도 똑같다. 용암 웅덩이 5곳(전부 체력 1 감소 후 밖으로 밀려남)과 위습 5마리(2.5초 동안 모두 이동)를 현재 좌표로 직접 확인했고 정상이다. 테스트가 v1.6.3 맵 확장(가로 2,400 → 3,627px) 이전 좌표와 v1.6.x 이전 규칙(강풍 20~30초, 깃발 5개, 위습 밟기)을 쓰고 있어서 실패한다. 테스트 갱신이 필요하다.

## 2. 기존 렌더링 조사 결과

**수인숲 (`renderer.js` → `drawThinPlatformVisual`)**
- 얇은 발판은 폭에 따라 세 갈래로 그린다. 117~184px는 `single_small` 한 장, 월드1의 200~308px는 `single_medium` 한 장, 그 외는 `left`/`middle_a·b·c`/`right` 모듈을 0.50배로 이어 붙인다(`makePlatformModulePlan`, 남는 폭은 `middle_a` 가운데를 잘라 채움).
- 숲 시제품 441×80은 바로 이 모듈 5개를 0.50배로 나란히 놓고 색만 보정한 그림이다. 원본 모듈과 픽셀 단위로 대조해 경계(0/70/170/270/370/441)를 확인했다. 그래서 이 경계로 잘라 배포본과 같은 배치 규칙에 1:1로 넣었다. 접지 행 21 = 배포본 `thinWalk 42 × 0.50`.

**정령산 동굴 (`spirit-mountain.js` → `drawSpiritTile`)**
- 동굴 구역(`M`으로 시작하는 발판)의 120px 이상 발판은 `cave_long`(1419×237, 표면 행 47)을 0.34배로 3분할(양끝 130px, 가운데 반복)해 그린다. 양쪽으로 6px씩 튀어나온다.
- 동굴 시제품 482×81은 이 `cave_long`의 0.34배 크기와 같다(1419×0.34 = 482, 접지 47×0.34 = 16). 그래서 같은 3분할(양끝 44px, 가운데 394px)을 1:1로 적용했다.
- 120px 미만은 `cave_tiny`, 점멸 발판은 `cave_glow`, 가비아 바닥은 `cave_long`을 바닥 폭에 맞춰 늘린 한 장이다.

## 4. 접지선 검증

측정 방법: 게임 루프를 멈춘 상태에서 같은 프레임을 발판 있음/없음으로 두 번 그려 차이 = 발판 픽셀. 발판 폭의 90% 이상이 칠해지는 첫 행을 "보이는 윗면"으로 잡고 두두의 물리 발 좌표(`p.y`)와 비교했다. 72개 발판에 두두를 실제로 세워서 쟀다(움직이는 발판 3개는 세우기 실패로 제외).

| 구분 | 수정 전 (보이는 윗면 − 발) | 수정 후 |
| --- | --- | --- |
| 숲, 폭 141px 이상 (21개) | 0~4px, 중앙값 0 | 0~4px, 중앙값 0 |
| 숲, 폭 141px 미만 좁은 발판 (35개) | 2~3px, 중앙값 2 | 2~4px, 중앙값 3 |
| 동굴 (16개) | 0px | **−7px** (15개), 0px (1개) |

- 숲: 그림 윗면 기준 행 21이 정확히 발판 y에 놓인다(오차 0px). 측정값에 보이는 0~4px는 잔디 끝의 반투명 픽셀과 배경색이 비슷해서 생기는 측정 편차이며, 수정 전에도 똑같이 나온다.
- 좁은 발판 1px 차이: 배포본은 96px 미만 발판을 약 0.49배로 아주 조금 줄여 그리는데, 시제품은 배율을 바꾸지 않는다는 원칙대로 1:1로 그렸기 때문이다.
- **동굴 −7px(승인 필요)**: 동굴 시제품은 위에서 내려다본 판석 모양이다. 윗면이 행 9~21(13px 두께), 앞쪽 모서리가 행 22이다. 메타데이터의 접지 행 16대로 두면 두두의 발은 윗면 한가운데에 서고, 판석 실루엣의 맨 윗선은 발보다 7px 위, 앞 모서리는 6px 아래에 보인다. 배포본 동굴은 발이 바위 윗선에 바로 붙어 있었다. 접지 행을 9로 바꾸면 발이 판석 맨 윗선에 서지만, 메타데이터와 다른 값이라 임의로 바꾸지 않았다. `contact_crops/SM-*.png`에서 확인 후 결정 필요.
- 두두 그림의 가장 아래 픽셀은 수정 전후 모두 발보다 3~4px 아래(v1.7.4에서 맞춘 꼬리 끝)이며 바뀌지 않았다.

## 5. 이미지 배율 검증

- 모든 `drawImage`가 원본 영역과 화면 영역을 같은 크기로 쓴다(`sx == sy == 1`). 카메라 확대도 측정한 모든 장면에서 1.0이었다.
- 단색 배경에 그린 띠 이미지에서 양끝 조각을 원본과 픽셀 단위로 대조: 동굴은 불투명 픽셀 전부 차이 0, 숲은 반투명 포함 전체 최대 차이 1(알파 합성 반올림).
- 실제 게임 화면에서는 빛줄기, 안개, 사탕 같은 위에 그려지는 것 때문에 일부 차이가 보이지만, 배율 차이는 아니다.
- 그림 위아래 크기: 숲 80px(배포본 81px), 동굴 81px(배포본 81px).

## 6. 이음매 검수 (`strips/`)

폭 92~1141px 발판을 단색 배경에 그려 양끝, 가운데 반복, 채움 조각을 확인했다.

- **숲**: 배포본과 같은 배치 규칙이라 이음매 위치도 같다. 두 가지는 원래부터 있던 것이다.
  - 폭이 100의 배수가 아닐 때 남는 폭을 `middle_a` 가운데 조각으로 채우는데, 흙 부분에 세로 줄이 보인다(예: 360px). 배포본에도 똑같이 있다.
  - 841px 이상에서는 가운데 조각의 작은 풀잎이 100px마다 같은 자리에 반복된다. 아트 바이블 "반복 중앙 파츠에 눈에 띄는 장식 재등장 금지"에 걸릴 수 있다. 에셋 쪽 수정 사항이다.
- **동굴**: 배포본 방식(가운데를 반복하다 남는 곳에서 자르기)을 그대로 쓰면 오른쪽 끝 조각과 만나는 곳에서 바닥 윤곽이 2~6px 계단처럼 끊기고 균열 선이 잘렸다. 시제품은 무늬가 단순해서 배포본보다 눈에 잘 띈다. 그래서 가운데 시작(열 44)과 끝(열 438)은 원래대로 두고, 남는 길이만큼 빼는 자리를 앞뒤 열이 가장 비슷한 곳으로 골라 자르게 했다. 그림은 1:1 그대로 옮겨 붙일 뿐 다시 그리지 않는다.

## 9. 승인 판단에 필요한 관찰 (수정하지 않음)

1. **스토리 수인숲과 색 차이**: 숲 시제품은 월드1의 어두운 숲 배경에 맞춰 채도를 낮췄다. 월드1에서는 잘 어울리지만, 밝은 들판인 스토리 수인숲에서는 바로 옆 땅(배포본 `ground_top`, 밝은 연두)보다 발판이 어둡고 탁해 보인다. 스토리 수인숲 배경 기준 색을 따로 정할지 결정이 필요하다.
2. **한 화면에 두 화풍**: 작은 발판(117~184px), 월드1 중간 발판(200~308px), 땅, 벽은 배포본 그림이라 한 화면에 새 그림과 옛 그림이 섞인다. 월드1은 바뀐 발판이 절반이 안 된다(54/112). `forest_small`, 중간 크기, 벽 에셋이 있어야 판단이 정확해진다.
3. **동굴 대비**: 시제품 회청색 판석은 배포본 보라빛 동굴 벽, 기둥과 색이 다르고, 어둠 마스크 안에서 배포본보다 윤곽이 덜 보인다(모바일 `cave_mid` 참고). 바이블의 "플레이 판독" 게이트 확인 필요.
4. **동굴 접지 행**: 4장 참고. 16 유지(윗면 가운데에 섬) 또는 9(실루엣 맨 위에 섬) 중 선택.
5. 월드1 1-1의 긴 잠금 발판 2개는 아래에 별도 흙벽 오브젝트(`W1-S1-WALL-*-UNDER`)가 겹쳐 그려져 잔디 윗부분만 새 그림으로 보인다. 배포본 구조 그대로다.

## 10. 실행 방법

```bash
python -m http.server 8000      # http://localhost:8000/index.html  (끄고 보기: index.html?arttest=0)
python tools/qa/art_inventory.py            # 먼저 실행 (다른 두 스크립트가 이 목록을 씀)
python tools/qa/art_prototype.py            # tools/qa/out/art/ 에 스크린샷과 art_prototype.json
python tools/qa/art_physics_identity.py
python tools/qa/art_file_open.py            # 파일로 열었을 때 (index.html 더블클릭과 같은 조건)
```

배포 브랜치(`main`)에는 합치지 않는다. 승인 후 정식 반영할 때는 `art-prototype.js`의 플래그 방식 대신 `renderer.js`/`spirit-mountain.js`에 직접 넣고 캐시 키를 올린다.
