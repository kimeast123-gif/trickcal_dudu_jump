## 2. 원본 MP3 파일과 게임 배포 경로

ZIP의 원본 위치:

```
05_BGM_RAW/20. Dragon Cave (Crystal).mp3
05_BGM_RAW/22. Deep Cave.mp3
05_BGM_RAW/23. Ghost Village.mp3
```

Claude가 실제 저장소에 복사할 대상 (복사하면서 파일명만 변경, **음원 바이트 변경 없음**):

```
assets/event/ghost_dragon_cave.mp3    ← 20. Dragon Cave (Crystal).mp3
assets/event/ghost_deep_cave.mp3      ← 22. Deep Cave.mp3
assets/event/ghost_village.mp3        ← 23. Ghost Village.mp3
```

이 경로는 현행 `event.js`의 `EVENT_ROOT='assets/event/'`에 맞춘 제안이다. 실제 최신 브랜치에 다른 오디오 모듈이 있으면 이를 우선 확인하되, 기존 트랙 인덱스·마스터 볼륨 규약은 깨뜨리지 말 것. **파일을 ZIP에서 참조하는 것이 아니라 게임 배포 디렉터리에 실제 복사**해야 한다.

## 3. 2026-11-22 빌드에서 확인한 실제 음악 처리 코드

- `event.js` 약 9~18행 `musicNames`, `BGM_LOOP_BOUNDS`가 트랙 목록과 루프 범위를 정한다.
- `event.js` 약 20~69행 `tracks`, `playTrack(n,restart)`, `musicTick(dt)`, `refreshMusicMasterVolume()`이 트랙 선택과 페이드, 일시정지/음소거/볼륨을 처리한다.
- `worldmap-mode.js` 약 1615행은 `playTrack(stg.musicTrack ?? 0, false)` 방식으로 스테이지 입장 음악을 시작한다.
- `worldmap-mode.js` 약 1531행 `stg.onLoad(opts)`는 **위 음악 선택보다 먼저 호출**되므로 `onLoad` 안에서 음악을 바꿔도, 마지막에 스테이지 기본 음악이 덮어쓸 수 있다. 4-3 구출 후 저장 상태는 스테이지 선택 시점에 해석하거나 음악 선택 이후 별도 동기화해야 한다.
- `worldmap-mode.js` 약 1668행 `stg.onReset()`이 재시작 뒤 호출되므로 BGM 복구도 이 지점에서 검토한다.
- `event.js`의 `eventTick` 월드모드 분기는 `musicTick`만 호출하며, 스토리모드 시간대 자동 BGM 교체(음악Stage)는 월드4에 **적용되지 않아야 한다**.

최소 변경 제안 (실제 코드 구조 확인 후 변경):

```js
// event.js 의 기존 musicNames 여섯 원소는 반드시 원래 인덱스 유지.
// 아래 3개만 배열 끝에 추가.
const musicNames = [
  'day', 'afternoon', 'sunset', 'opening', 'ending', 'monatium',
  'ghost_dragon_cave', 'ghost_deep_cave', 'ghost_village'
];
window.GHOST_BGM_TRACKS = Object.freeze({ DRAGON: 6, DEEP: 7, VILLAGE: 8 });

// BGM_LOOP_BOUNDS 에 세 항목 추가 (시작값은 실기 조정 가능):
// ghost_dragon_cave: {start:0.05, end:46.30},
// ghost_deep_cave: {start:0.05, end:52.19},
// ghost_village: {start:0.05, end:49.05},

// 월드4 4-1: musicTrack: 6
// 월드4 4-2: musicTrack: 8
// 월드4 4-3: musicTrack: 7
// 구출 완료 상태 전이 시 1회: playTrack(6, false);
// 구출 후 체크포인트 진입/재시작 시에도 BGM 6 동기화 필수.
```

**주의:** 위는 게임에 직접 붙여 넣는 완성 패치가 아니라 적용 위치·값에 대한 예시다. `musicNames`를 두 번 선언하거나 기존 스토리 BGM을 덮어쓰지 않는다. `playTrack(n, false)`는 이미 선택된 음악에 대해 불필요한 재시작을 방지한다. `playTrack`의 기본 구현은 `scenePaused`에서 음악도 멈추므로, 4-3 구조상 ‘게임 조작 잠금 컷신’과 ‘실제 일시정지’를 분리해 구출 씬에서 원치 않는 긴 무음이 생기지 않도록 검증한다. 일반 일시정지·앱 백그라운드에서는 기존 정지 동작을 보존한다.

## 4. 반복/전환·볼륨 제약

MP3 3곡은 모두 44.1kHz 스테레오. 종료 직전에 약 1.4~1.7초의 무음이 검출됐다. 현행 게임은 루프 경계로 `loopStartSec`과 `loopEndSec`을 직접 제어한다. 무음을 불필요하게 반복하지 않도록 다음 **시험용 초기값**을 제안한다.

| 원곡 | 총 길이 | 검출된 말미 무음 시작 | 초기 loopStart | 초기 loopEnd |
|---|---:|---:|---:|---:|
| 20 Dragon Cave (Crystal) | 48.013초 | 46.343초 | 0.05초 | **46.30초** |
| 22 Deep Cave | 54.021초 | 52.231초 | 0.05초 | **52.19초** |
| 23 Ghost Village | 50.573초 | 49.091초 | 0.05초 | **49.05초** |

측정: `ffmpeg -af silencedetect=noise=-45dB:d=0.25`; 검출은 주파수 분석이 아닌 음량 기준이며 **완벽한 음악적 반복 지점이라는 뜻이 아니다.** 실제 2회 이상 연속 반복을 듣고 끊김/클릭/비트 어긋남이 있으면 루프 끝점을 조정하거나 짧은 크로스페이드 루프를 적용한다. 전체 무음을 그대로 반복해 ‘음악이 멈췄다 다시 나오는’ 현상은 피한다.

- 스테이지 BGM 변경은 중복 `HTMLAudioElement`를 별도 생성하지 않고 **기존 `playTrack/musicTick` 경로** 사용. 기존 구현의 전체 볼륨 슬라이더·음소거·재개 규칙 유지.
- 게임 기본 음악과 4-1/4-2/4-3 음악 동시 재생 금지. 복귀 시 다른 월드의 BGM 잔재 금지.
- 배경 bg2→bg3는 음악 전환 아님, bg4→bg5는 **구출 완료 시의 음악 전환과 동기화**.
- 첫 진입에서 브라우저 오디오 자동재생이 막힌 경우 기존 사용자 클릭/음악 켜기 경로를 사용하고 오류를 무한 반복시키지 않는다.
- 체크포인트 재시작, R 재시작, HP 0, 강제 리셋, 브라우저 일시정지, 모바일 환경의 화면 전환/재진입 모두 같은 규칙 적용.
